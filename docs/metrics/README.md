# Metrics Artifacts

This folder stores lightweight current-state artifacts generated by runtime hardening scripts. Recurring reports overwrite a stable `*-latest.json` path; Git history preserves prior revisions without accumulating timestamped copies in the current tree.

## Files

- `agent-runtime-latest.json` — last eval run report (overwritten on each recorded run)
- `agent-runtime-history.jsonl` — append-only run history (one JSON object per line)
- `autonomy-self-work-*.json` — sanitized self-work runner readiness, policy, verification, and approval artifacts
- `dependabot-security-audit-latest.json` — current dependency-alert classification posture
- `github-security-posture-latest.json` — current sanitized GitHub Dependabot/code/secret open-count posture, including source and metadata limitations
- `dependency-risk-posture-latest.json` — current dependency and lifecycle-script posture
- `infra-hardening-latest.json` — current infrastructure hardening audit
- `phone-local-acceptance-latest.json` — current sanitized physical-device acceptance posture
- `readiness-rollup-latest.json` — versioned `webCandidate`, Desktop, and Phone/PWA readiness lanes with evidence expiry, truthful seven-state posture, blockers, and one strongest safe next action. The active web label is `Web candidate (v1.0.0-rc.2)`; future candidate names do not require another schema-key rename, and deferred Phone/PWA or Desktop work does not block the web candidate
- `release-diagnostics-latest.json` — current release diagnostics snapshot
- `cp2-staged-release-rehearsal-latest.json` — current HTTPS staged smoke/diagnostics posture using only a sanitized target identity; diagnostics never count as rollback proof
- `docker-release-proof-latest.json` — current fail-closed exact-source image/build/run identity posture; the artifact exists and remains blocked until the immutable tag and a compatible Docker proof environment are available
- `web-staging-assurance-latest.json` — expected stable read-only HTTPS target assurance across identity, auth, routes, feeds, capabilities, and protected-action posture; missing until a staged target is available
- `protected-action-proof-latest.json` — expected stable, sanitized proof for one exact server-reported approval-required action receipt; web assurance accepts it only when its schema, freshness, bounded request, shared-key HMAC, verified semantics, exact run ID, and keyed target ID all match. The HMAC proves key possession and tamper resistance inside the trusted operator/runtime boundary, not independent server or provider provenance
- `known-good-deployment-latest.json` — expected signed identity for the first fully passing staged deployment, bound to matching current diagnostics, web assurance, and protected-action evidence. The recorder refuses to overwrite an existing baseline; replacement requires a separately approved rotation
- `rollback-proof-latest.json` — expected signed proof of an operator-confirmed platform rollback plus measured restored source/image identity, new boot identity, and fresh bound postchecks. It is not direct deployment-provider API attestation and remains missing until a real platform rollback is performed
- `desktop-trust-chain-latest.json` — current desktop checksum, signing, and SBOM posture
- `cp2-operational-live-gate-latest.json` — current operational live-gate result

Timestamped copies of these recurring report families are intentionally rejected by `npm run metrics:retention:check`.

## Generate

- Local record run:
  - `npm run eval:agent-runtime:record`
- CI gate (threshold only, no artifact persistence in CI workspace):
  - `npm run eval:agent-runtime:ci`
- Self-work readiness:
  - `npm run autonomy:self-work`
- After a staged deployment has fully passing diagnostics and assurance, record
  its immutable known-good identity with `npm run staging:known-good:record`.
- After the separately approved protected action completes, capture its exact
  receipt with `npm run staging:protected-action:proof -- --run-id=<approved-run-id>`;
  `NEXUS_EVIDENCE_KEY` identifies the target independently from `NEXUS_TOKEN`
  and authenticates the evidence inside the shared operator/runtime trust boundary.
- After an operator performs the real platform rollback, verify fresh restored
  evidence with `npm run staging:rollback:verify -- --started-at=<ISO> --confirm=I_PERFORMED_PLATFORM_ROLLBACK`.

Rollback-chain inputs must be no more than 24 hours old when validated, and
their declared expiry window cannot extend more than 24 hours beyond capture.

## Thresholds

- Global threshold: `--min-score`
- Category thresholds (repeatable):
  - `--min-category safety=80`
  - `--min-category reliability=80`
  - `--min-category ux=70`
  - `--min-category observability=70`
