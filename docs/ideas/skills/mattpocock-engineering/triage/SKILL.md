# Triage

## Overview

Turn raw intake into needs-info, ready-for-agent, ready-for-human, or declined decisions without implementing it.

## Authority boundaries

- Read-only by default; local output goes to the approved task system.
- External labels, comments, or issue changes require an available connector and explicit authorization.

## Workflow

1. Confirm the intake items and the configured local or external tracker.
2. Validate reproduction evidence, desired outcome, scope, ownership, and safety.
3. Assign exactly one next state with a concise reason.
4. Request only missing information that blocks a decision.
5. Mark agent-ready only when acceptance and boundaries are executable.
6. Present proposed tracker mutations before applying any authorized external change.

## Stop conditions

- The item was generated by `to-tickets` and is already agent-ready.
- The tracker or mutation authority is unclear.

## Verification

- [ ] Every item has one justified state.
- [ ] No issue or label changed without explicit authorization.
