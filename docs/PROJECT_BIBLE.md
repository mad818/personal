# Nexus Prime Project Bible

## What Nexus Is

Nexus Prime is a local-first command-and-intelligence workspace that combines:

- assistant-led HQ conversation
- specialist workspaces for markets, cyber, recon, vault, and resources
- durable continuity across sessions, artifacts, and exact workspaces

It is not a cloud SaaS dashboard and not an academic-only research app. It is an operator-grade system for thinking, deciding, building, researching, and compounding knowledge locally.

## Core Product Guarantees

1. Free-first and local-first remain non-negotiable.
2. Nexus does not charge users in-app. Optional keys are BYOK.
3. Web routes stay exact-session friendly: stateful links should reopen the strongest valid workspace rather than dropping the user onto generic route tops.
4. The assistant remains the default entrypoint. Other surfaces exist to deepen work, not to replace the assistant with dashboard sprawl.
5. Honest degradation matters. If retrieval, providers, or workspace recovery are unavailable, the system should say so plainly instead of pretending certainty.
6. Nexus uses selective context loading. Most project knowledge should stay addressable and sliceable rather than ambient in every turn.

## User And Operator Model

- Primary user: a single operator who works across research, engineering, security, markets, and workflow orchestration.
- Operating stance: assistant-first, exact-session aware, compact, and continuity-driven.
- Collaboration model: the human decides priorities and direction; the system should stage the best next workspace and reduce manual navigation overhead.

## Surface Map

### GA Surfaces

- `HQ` — conversational entrypoint, assistant orchestration, prepared workspaces
- `COMMAND` — system posture, operational brief, programs, context memory
- `INTEL` — news, theater posture, cross-domain impact, forecast, sweep workbench
- `ALPHA` — market brief, setups, momentum, risk plan, market tape
- `CYBER` — threat brief, priority grid, evidence feeds, physical ops
- `RECON` — collection workbench, binary analysis, operator safety
- `VAULT` — memory brief, archive workbench, durable artifacts, relations
- `RESOURCES` — manuals, specs, playbooks, study/research workbench, exact-session launchers

### Internal Or Specialist Surfaces

- `SKILLS` — control plane for system brain, workflow defaults, and capability settings
- Additional internal or beta surfaces can exist, but they should not displace the GA assistant-first contract.

## Long-Horizon Direction

Nexus should keep moving toward:

1. one assistant-led operating system with specialist workspaces behind it
2. passive memory and research compounding instead of manual maintenance-first workflows
3. deterministic continuity, promotion, and recovery instead of fragile route heuristics
4. strong local deployment and release discipline so the product is trustworthy in real hosted conditions

## Product Boundaries

- No new GA tabs are required to assimilate ideas from outside repos.
- External repos should influence behavior, routing, continuity, source handling, and workflow discipline before they influence visible UI.
- Desktop work is important, but the web lane is the first public proof path.
