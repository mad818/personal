# Nexus Prime v1.0.0-rc.1

Status: published on 2026-08-11 after Mario's explicit approval.

This release candidate brings the public Nexus showcase and the adaptive
capability-assurance layer into one baseline. The result is easier to evaluate:
the README shows what the product does, while the application shows whether a
capability is merely declared, recently verified, degraded, retained,
unavailable, or waiting for approval.

## Highlights

- Eight supported operator surfaces: CITADEL, VECTOR, SPECTRA, QUANT, BASTION,
  PARALLAX, ARCHIVE, and FIELD MANUAL.
- Five specialist agents coordinated through the existing governed runtime.
- Thirteen versioned capability contracts with information, action,
  prerequisite, verification, recovery, and efficiency semantics.
- Prompt-free local outcome receipts and human-approved reinforcement.
- A privacy-reviewed public product capture plus current route artwork.
- Free/local Ollama by default, with explicit BYOK providers available when the
  operator chooses them.
- Health-gated local startup and one canonical Tauri standalone build path.
- Zero vulnerabilities in the live npm audit after raising the global
  `brace-expansion` floor to `5.0.9`.

## Repository cleanup

- Replaced the old product changelog with a Nexus release record.
- Collapsed recurring evidence into stable current artifacts.
- Removed duplicate generated desktop output and unreferenced public showcase
  exports from Git tracking.
- Made agent workspace state local-only and retired the unsupported launcher
  from the published tree.
- Kept existing Git history, required archives, active tests, security policy,
  recovery material, and desktop build inputs intact.

## Migration notes

- Start Nexus with `NexusPrime.bat` or `npm run operational:start`.
- Rebuild desktop output with `npm run desktop:build-runtime`; do not depend on
  a checked-in `desktop/frontend-dist/` snapshot.
- Existing local `agent-workspace/` data stays local. Fresh clones create it as
  needed from source-controlled defaults.

## Known limits

- Phone and iPad acceptance is intentionally deferred.
- Signed desktop installers and their checksums are not yet published.
- Docker and staged-host release proof still depend on the target environment.
- Live feeds and optional AI providers remain subject to their configured keys,
  network mode, rate limits, and honest unavailable states.
