# Workflow Pattern Family Closure

## Outcome

Close the feasible workflow, agent-discipline, conversation, configuration, reporting, and scheduling patterns recorded from Ponytail, the reviewed agency pack, the Fainir prompt, Formbricks, Cal.diy, Chatwoot, ERPNext, and Listmonk through current project-native behavior.

## Product behavior

1. Every agent runtime clamps requested iterations to a fixed project maximum.
2. Tool availability remains capability-, network-, connector-, and approval-gated.
3. MAX delegation and typed specialist handoffs provide role-based decomposition without vendoring untrusted personas.
4. Existing conditional composer states, workflow schemas, filtered registries, saved audit views, conversation quick actions, and AI response flow serve the relevant UI patterns.
5. The scheduler composer gains a browser-local availability planner:
   - explicit local date, work window, slot length, and busy ranges;
   - strict bounded parsing and overlap merging;
   - open-slot computation with runtime fixtures;
   - click-to-fill recurring daily cron;
   - explicit no-calendar-sync truth.
6. Source-specific products, runtimes, global host control, survey/customer-support/ERP/newsletter platforms, and speculative infrastructure splits remain excluded where they do not serve Nexus.

## Verification

- `npm run workflow-patterns:check`
- `npm run scheduler:availability:check`
- `npm run source:parity:check`
- `npm run type-check`
- focused zero-warning lint

## Benefits

- Scheduling decisions can use real local availability instead of mental arithmetic.
- Agent loops cannot accept unbounded iteration requests.
- Existing mature Nexus surfaces receive credit only where the behavior is genuinely reachable and checked.
- Large external platforms do not become duplicate subsystems.
