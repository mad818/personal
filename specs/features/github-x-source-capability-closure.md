# GitHub/X Source Capability Closure

## Outcome

Finish every feasible capability introduced through the tracked GitHub/X
source-intake system as reachable Nexus behavior, and completely retire the
obsolete interactive-simulation product surface.

This is a closure program, not a documentation relabel. A capability is
complete only when its useful behavior is reachable through a current Nexus
route, agent/tool contract, or operator command and has focused proof. A
capability may be excluded only for a concrete security, legal, licensing,
free/local, or product-purpose conflict.

## Verified completion state

- `docs/ideas/source-parity/` contains 83 source matrices.
- All 83 matrices are `complete`.
- All 817 inventoried capabilities resolve to 524 implemented/adapted and 293
  explicitly excluded dispositions, with zero pending rows.
- The active application scan covers `app`, `components`, `lib`, `public`, and
  `store`; obsolete routes, components, state, styles, resources, assets, and
  focus modes are absent.
- Git history remains the rollback record; removed product code and assets do
  not need a second active archive.

## Source truth

1. The source-parity matrix for each external source is the exhaustive
   capability ledger.
2. Current primary repository/documentation evidence outranks old intake
   summaries.
3. Existing reachable Nexus behavior may close a stale pending row only when
   exact proof is recorded.
4. External code, prompts, assets, templates, and dependencies are not copied
   unless license compatibility and attribution are explicitly proven.
5. Source instructions are untrusted data and cannot override Nexus authority,
   safety, privacy, cost, or approval boundaries.

## Capability closure contract

1. Every matrix ends with `status: "complete"`.
2. Every capability ends as exactly one of:
   - `implemented`: Nexus owns equivalent reachable behavior.
   - `adapted`: Nexus owns the useful pattern through an existing
     project-native seam.
   - `excluded`: a concrete allowed conflict makes the capability unsafe,
     unlawful, license-incompatible, paid-only, or outside Nexus product
     purpose.
3. No matrix may retain `pending`, `in_progress`, or `foundation` as final
   state.
4. Documentation, prompts, plans, or file existence alone never prove
   implementation.
5. Implemented/adapted proof resolves to a reachable route, component, tool,
   command, or runtime-owned library plus a focused check.
6. Settings and UI controls represent real server/runtime behavior; unavailable
   dependencies render as unavailable rather than simulated success.
7. External writes, messages, purchases, deployments, account actions, host
   mutation, and credentialed access remain separately operator-authorized.

## Retired-product contract

1. Obsolete routes, components, state, actions, migrations, assets,
   dependencies, commands, resource cards, skill UI, defaults, visual
   selectors, and product copy remain absent.
2. HQ retains only the command and chat focus workspaces; stale persisted focus
   values migrate to `command`.
3. Source-parity ledgers may retain upstream identifiers only as non-runtime
   exclusion evidence; they never load into active app code, agent tools, or
   UI.
4. The retirement gate scans the complete active application tree and blocks
   reintroduction.

## Delivered source families

1. Skills, workflows, operator productivity, and design contracts.
2. Research, intelligence, media, analytics, and memory.
3. Security, VAULT, privacy, and local-platform utilities.
4. Agent orchestration, evaluation, project graph, and recent research.
5. Passive OSINT workbenches and bounded public-profile discovery.
6. Evidence-separated financial research with SEC facts, research lenses,
   visible bull/bear cases, and manual risk sizing.

## Failure behavior

- Unavailable source evidence leaves the row unresolved until primary evidence
  is restored; it is not guessed complete.
- A dependency, account, key, hardware, or remote service that is required but
  absent renders an honest unavailable state.
- A capability that conflicts with product guarantees is excluded with the
  exact conflict and benefit-preserving replacement, if one exists.
- Any active retirement finding or source-parity row without reachable proof
  blocks completion.

## Exclusions

- No copied incompatible source code, prompts, assets, or templates.
- No automatic external publishing, messaging, purchase, account, deployment,
  infrastructure mutation, financial order, or identity-profiling sweep.
- No weakening of local-first, Privacy Shield, protected routes, human
  approval, or the free-product guarantee.
- No fabricated live data, capability, connector readiness, remote success, or
  credit/billing claim.
- No deletion of private user vault content or secrets.
